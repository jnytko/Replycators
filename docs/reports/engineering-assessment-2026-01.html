8.ADR Template

Individual ADRs are stored as docs/adr/ADR-NNN-title.md. The template is at docs/adr/ADR-TEMPLATE.md. ADR-009 (Prompt Catalog decision) has been filed at docs/adr/ADR-009-prompt-catalog.md.

Required ADR sections

  1. Status - Draft | Active | Superseded by ADR-NNN | Deprecated
  2. Date - YYYY-MM-DD
  3. Context - Problem statement and constraints (1-3 paragraphs)
  4. Decision - Clear, unambiguous statement + rationale (<100 words)
  5. Alternatives Considered - Each with pros, cons, and reason rejected
  6. Impact - Positive, negative, neutral consequences + affected files
  7. Risks - Likelihood, impact, mitigation per risk
  8. Follow-up Actions - Checklist of required changes
  9. Change History - Version, date, author, change

Architecture Review Triggers (when to create an ADR)

  • Introducing a new persistence mechanism
  • Changing the plugin registration contract
  • Adding new host permissions
  • Changing popup/side panel interaction model
  • Introducing a new background service
  • Changing the build toolchain

12.Architecture Overview

12.1 System Context

[User: Support Engineer] + Popup / Side Panel [ReplyCators Extension] + Content Scripts -> [Salesforce Lightning] (DOM extraction) + XHR Interception -> [Cloudability] (OrgID detection) + chrome.tabs.create -> [Apptio Products] (dashboard launching) + HTTP -> localhost -> [IBM Bob CLI] (prompt execution) + chrome.* APIs -> [Microsoft Edge] (storage, tabs, bookmarks)

12.2 Startup Sequence

Browser opens popup -> dashboard.html loads -> plugins/*.js (x10) -- each registers on window.ReplyCatorsPlugins -> dashboard.js -- DOMContentLoaded handler -> restoreSession() -- SINGLE chrome.storage.local.get() for ALL keys -> applyAllSettings() (theme, font, density) -> applyPluginVisibility() (build nav from PLUGINS[]) -> applyDashboardOrder() (reorder widgets + nav) -> plugin.init() x10 (synchronous only -- no I/O) -> navigateTo(lastView) (restore last active view) -> Extension ready (~100ms)
